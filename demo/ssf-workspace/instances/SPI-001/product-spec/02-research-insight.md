## 2. 调研目标

- 要验证的问题：用户在“短时间获取新闻”时最需要摘要、排序、标签、来源透明还是深读入口。
- 要识别的用户：高频新闻用户、轻量新闻用户、垂直领域追踪用户、通勤碎片阅读用户。
- 要观察的现场 / 业务流程：早晨打开 App、通勤刷新闻、突发新闻提醒、围绕某个兴趣持续跟踪。
- 要参考的竞品：Google News、Apple News、SmartNews、Feedly、Ground News。
- 要支撑的设计决策：首页组织方式、标签体系、摘要层级、事件聚合、反馈训练、通知策略、可信度表达。

## 4. 市场 / 行业背景

| 观察项 | 内容 | 对产品设计的影响 | 关联洞察 ID |
|---|---|---|---|
| 个性化已是主流 | Google News 支持关注主题、地点和来源，也支持喜欢、不喜欢、隐藏来源等反馈 | 仅有“标签”不足，需设计持续反馈和来源控制 | INS-002 / INS-006 |
| 编辑精选与算法并存 | Apple News 同时强调编辑精选、个性化推荐、隐私和本地新闻 | 快读产品要在算法效率与可信编辑感之间建立平衡 | INS-005 |
| 快速阅读诉求强 | SmartNews 明确强调减少滚动、关注主题和出版方、多视角 | 本产品核心不应是无限流，而应是短时简报和可控兴趣 | INS-001 / INS-007 |
| 垂直追踪需要去噪 | Feedly 强调来源组织、AI Feed、去重、静音、摘要和规则化追踪 | 专业用户需要更强标签规则、排除条件和来源范围 | INS-003 / INS-006 |
| 信任和视角成为差异化 | Ground News 强调来源比较、Daily Briefing、多视角和本地新闻 | 对争议内容要给出来源透明和多角度入口 | INS-005 |

## 6. 调研洞察汇总

| insight_id | 洞察 | 来源 | 证据 ID | 产品设计影响 | 可能转化方向 |
|---|---|---|---|---|---|

| INS-002 | 显式标签是用户控制感的核心入口 | 用户 | RAW-004 / FACT-003 | 标签必须是一级能力，不应藏在设置深处 | 功能 / 产品架构 / UI |

| INS-004 | 同一事件重复报道会吞噬注意力 | 模型假设 / 竞品 | PAIN-003 / COMP-005 | 需要事件聚合和多来源列表，而不是平铺文章 | 产品架构 / 功能 |
| INS-005 | 新闻可信度和视角透明会影响用户是否接受摘要 | 竞品 / 模型假设 | SRC-102 / SRC-103 / SRC-105 / PAIN-004 | 摘要必须显示来源、时间和深读入口 | UI / 规则 / 验收 |
